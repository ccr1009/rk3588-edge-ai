# 接线复原图 —— 「11-03 能用的那套」到底怎么接

> 用途：忘了之前怎么接的时候，照这张图复原。
> 依据：README 3.1 / 3.2 / 3.3 + 8.1.1 实测记录（2026-11-03）。
> 那天实测结果：**摇臂自锁、`P ±35 0` 跟随摆动 18 秒、24 条命令全 OK、零错误。**

---

## 一、先看清一件事：接线分两套独立的系统

接线接乱，通常是因为没分清这是**两套独立的电路**：

| | 谁供谁的电 | 走哪几根线 |
| :--- | :--- | :--- |
| **A. 通信路** | ESP32 自己（RK3588 的 USB 供） | ESP32 的 USB 口 → RK3588 |
| **B. 舵机动力路** | 外部 5V 电源 | 外部电源 → 舵机 红/棕 两根 |

**这两条路只有一个连接点：GND（共地）。** 别的都不许交叉：
- 通信路的 5V 不许给舵机用（会把 RK3588 的 USB 口拉垮）
- 舵机电源的 5V 不许接进 ESP32 的 `5Vin`（那是输入脚，反灌）

> 一句话记法：**「5V 各走各的，GND 必须共享」。**

---

## 二、完整接线（照这个接）

### A. 通信路（今天已经在正常工作，不用改）

```
ESP32-S3 的【USB】Type-C 口  ──── USB 线 ────►  RK3588 的 USB 口
```

- 板子从 RK3588 取电
- 通信走 pyusb（`303a:1001`），已验证 `I` → `GPIN 14 15`

### B. 舵机动力路（★ 今天出问题的地方，照 11-03 复原）

```
外部 5V 电源 OUT+  ─────────────────►  舵机 红线 (VCC)

外部 5V 电源 OUT-  ──┬──────────────►  舵机 棕/黑线 (GND)
                     │
                     └──────────────►  ESP32 的【GND】针
                                              ↑
                                     这根线 = 共地，死线
                                     没有它舵机收不到信号
```

### C. 信号路（一根）

```
舵机 橙线 (PWM)  ───────────────────►  ESP32 的 GPIO14
```

**总数：5 根线。** 三根给舵机（红/棕/橙），一根共地，一根 USB。

---

## 三、最容易搞错的三个点

### ❌ 错误 1：舵机红线接 ESP32 的 `5Vin`

```
舵机红线 ──► ESP32 的 5Vin 针        ← 错！一点电都没有
```

`5Vin` 是**电源输入脚**（从外部给板子供电用），USB 供的电**不会**从它倒流出来。
这是本项目 11-03 卡两天的第三个真根因（README 踩坑第 6 条 ③）。

> 我在 11-04 的对话里建议你这么接过 —— 那是错的，已更正。

### ❌ 错误 2：以为 ESP32 的 USB 5V 能给舵机用

ESP32 板子上的 3V3 / 5V 输出针，**总输出能力只有几百 mA**。
SG90 堵转 1.4A/颗，接上去会：
- 电压瞬间塌陷 → 舵机没劲
- 把 RK3588 的 USB 口拉垮 → ESP32 掉线（`error -71` / `-32`）

**历史证据**（README 踩坑第 8 条）：CH340 和 UVC 摄像头在**同一秒**一起掉线，
因为它们挂在两个不同的 USB Hub 上，唯一公共点就是 5V 供电轨。

### ❌ 错误 3：忘了那根共地线

```
   外部 5V 电源 OUT- ──► 舵机棕线        ← 只接了这一根 = 不共地
                                           舵机照样不工作！
```

舵机的 GND 和 ESP32 的 GND **必须是同一个电气点**。
因为 PWM 是「相对 GND 的电压」，两边 GND 不连通，舵机看到的
就不是 3.3V 方波，而是一团没有参考电平的乱信号。

**症状正好是：完全没自锁力、一点声音都没有、摇臂很松。**

## 四、用哪个 5V 电源？

那天用的是 **USB 转 TTL 模块**的 5V（CH340，`1a86:7523`）。
现在你有 DC 12V→5V 模块，两个都能用，区别是：

| 电源 | 优点 | 缺点 | 建议 |
| :--- | :--- | :--- | :--- |
| **USB转TTL 模块 5V** | 11-03 实测跑通过 | 电流小；模块从板子 USB 取电，堵转会把板子拉垮 | ✅ **先用这个复原**（已验证） |
| **DC 12V→5V 模块** | 电流足，能带两颗舵机 | 需要额外一根共地线连到 ESP32 | ⏳ 复原成功后再换 |

**策略：先用已验证方案复原，确认舵机是好的，再升级电源。**
不要一上来就上 DC 模块 + 双舵机 —— 那正是今天出问题的组合。

> 如果你的 USB转TTL 模块已经找不到了/不好接，用 DC 模块也行，
> 但**必须补上那根共地线**：`DC 模块 OUT- ──一根线── ESP32 GND`。

## 五、接完怎么验证（不用万用表）

### 第一步：摇臂手感（最直接的判据）

断电状态下拨一下摇臂，然后通电，**不要发任何命令**，再拨一次：

| 手感 | 含义 |
| :--- | :--- |
| 通电后**捏不动 / 松手回弹** | ✅ 电 + PWM 都到位了 |
| 通电后**还是轻轻一拨就转** | ❌ 缺电 或 没共地 或 信号没到 |

这一步不需要任何工具，也能区分「有电」和「没电」。

### 第二步：让 ESP32 自测量波形

```bash
ssh root@<board-ip>
bash /root/esp32_gimbal/stop_bridge.sh
/root/rknn_env/bin/python /root/esp32_gimbal/diag_usb.py
```

期望看到：
```
LB pin=14 edges=102 high=51 pw_avg=1499us pw_min=1499us pw_max=1499us per_avg=20000us n=51
```

这证明**信号侧完全正常**（已经验证过了）。
如果摇臂还是松，那就只剩供电/共地/舵机坏了三种可能。

### 第三步：让它摆起来看

```bash
/root/rknn_env/bin/python /root/esp32_gimbal/servo_live.py
```

舵机会连续左右摆（每边 4 秒），**不限时，什么时候看都行**。
停止：`servo_live.py stop`

## 六、如果复原了还是不动：按这个顺序排查

**每次只改一处，改完立刻测，记下来。改线前先断电。**

| 步 | 只改这一处 | 如果动了 → 结论 |
| :-: | :--- | :--- |
| 1 | 确认共地线真的接上了（模块 GND → ESP32 GND） | 就是共地问题 |
| 2 | 确认红线接的是**模块 OUT+**，不是 ESP32 `5Vin` | 就是 `5Vin` 接错 |
| 3 | 换一根杜邦线（尤其橙线） | 线材断芯 |
| 4 | 换一个舵机 | 原舵机烧了 |
| 5 | 只留一颗舵机（拔掉 tilt） | 双舵机电流不够 |

**止损点**：1~4 步做完还是不动 → 买万用表（¥30）或买备件舵机（MG90S ¥15）。
盲改超过 5 次，就该停下来买工具，而不是继续猜。

---

## 七、复原成功之后，再往上加

顺序不能跳，每步都确认舵机是活的：

1. **单舵机 + USB-TTL 模块 5V** ← 先回到这里（11-03 状态）
2. 加第二颗舵机 → 但供电必须换 DC 模块（两颗峰值 2.8A，TTL 模块带不动）
3. 换 DC 模块时，**额外那根共地线一定要接**
4. 加 tilt 后跑 `calibrate_tilt.py` 标方向（见 `NEXT_TILT.md`）

---

## 八、一句话总结

> **舵机要工作，只需要三件事同时成立：**
>
> **① 红线有真的 5V** —— 从外部电源来，不是 ESP32 的 `5Vin`（那是输入脚）
> **② 棕线和 ESP32 的 GND 是同一个电气点** —— 共地，缺了信号就没有参考电平
> **③ 橙线在 GPIO14 上有 50Hz PWM** —— 已实测 `pw_avg=1499us / per_avg=20000us` ✅
>
> **第 ③ 条已经用实测数据证实没问题了。所以问题一定在 ① 或 ②。**
>
> 而 ① 和 ② 的症状完全一样（没声、没锁、摇臂松）——
> 这就是为什么需要万用表，或者需要「每次只改一处」的纪律。
