## 二、三个被修掉的 bug（按重要性）

### bug 1：★★★ DTR/RTS 拉高让 ESP32 持续复位

**现象**：`lsusb` 能看到 `303a:1001`，pyusb 也能打开 CDC，但发 `I` 命令 0 回应，
被动监听 5 秒也是 0 行。看起来完全像"固件卡死"，差点去重烧固件。

**根因**：`usb_cdc_serial.py` 里固定发

```python
dev.ctrl_transfer(0x21, CDC_SET_CONTROL_LINE_STATE, 0x03, ctrl_num, None)
```

`0x03` = DTR + RTS 都拉高。对 ESP32-S3 的 USB-Serial-JTAG 来说，
这等价于**按住自动下载电路**（EN / IO0）→ 芯片反复复位 →
`app_main` 永远跑不到处理命令那一步。

但 **USB 描述符是芯片 ROM 提供的，app 没跑也照样在**，
所以出现"能枚举、能打开、但不回话"这种极有迷惑性的组合。

**逐组实测**：

| DTR/RTS | 结果 |
| :--- | :--- |
| `0x03`（都拉高） | ❌ 0 回应 |
| **`0x00`（都拉低）** | ✅ **`GPIN 14 15`** |
| `0x01`（只 DTR） | ❌ 无回应 |

**修复**：改成 `0x00`，并加**自动探活**——打开后发一次 `I`，
没回应就依次试 `0x03/0x01/0x02`，找到能通的那个。换板子/换固件版本都不会卡死。

**教训**：**「能打开」和「能通信」是两件事。** 判据必须是"收到正确回包"，
不能是"打开没报错"。

---

### bug 2：★★ 测试脚本误发 `X` 命令，PWM 全发到错误引脚

**现象**：`I` 返回 `GPIN 40 15`，几分钟前还是 `GPIN 14 15`。
整个舵机测试期间舵机不动。

**根因**：`definitive_test.py` 第一版把 `X` 当成"重置状态"放进清场命令：

```python
for c in ["D 0", "A", "X", "P 0 0"]:    # ← X 不是重置！
    one(ser, c, 0.3)
```

但固件里 `X` = `start_scan()`：

```c
case 'X':
    start_scan();     // 开始遍历 SCAN_PINS[]，每 1.2s 换一个脚
```

而主循环里扫描优先级最高：

```c
if (g_demo)          update_demo(...);
else if (g_toggling) update_toggle();
else if (g_scanning) update_scan();        // ← 扫描期间 P 命令完全不生效
else                 update_slew(...);
```

于是 `g_pan_pin` 被每 1.2 秒换一次（14 → 15 → 16 → … → 40 → …），
**整个测试的 PWM 都发在错误的引脚上**，舵机当然不动。

**如果没有发现这个，会误判成"舵机坏了"** —— 虽然最终结论恰好也是舵机坏了，
但那是运气，不是推理。

**修复**：
- 清场只发真正停止类命令：`D 0`（停演示）、`A`（停翻转）
- 加前置检查：确认 `I` 回 `GPIN 14`，不对就等扫描跑完（24 脚 × 1.2s ≈ 29 秒）

### bug 3：调参脚本的判定逻辑把"没目标"当成"最稳"

**现象**：第一次 settle 扫描，第 4、5 轮 `tilt 标准差 = 0.00°`，
脚本判定它们"最稳"并推荐。

**根因**：`tilt` 全程不动有两种完全相反的解读：

- **真的稳**（好，说明参数压住了抖动）
- **根本没检测到人**（坏，`tilt` 停在某个值从没变过）

脚本只看标准差，把第二种当成了第一种。

**修复**：用 `LOCK` / `TRACK` 出现帧数作门槛，少于 8 帧直接标"无效"。

**教训**：**"没变化"是最危险的测量结果** —— 它既可能是"很好"，
也可能是"根本没测到"。必须有第二个独立指标来区分。

## 三、最终的真相：摄像头装反了

调参折腾了半小时，抓快照一看：

```
HUD:  Gimbal P+0.0 T-0.1 | LOST | obj 0
检测框: keyboard 75% 537x582
        mouse    79% 222x82
```

**画面里是键盘和鼠标 —— 摄像头物理上朝下对着桌面。**

所以：

```
摄像头朝下 → 检测不到人（obj 0） → 全程 LOST
          → T 一直是 -0.1°，从没被驱动过 → 舵机不动
```

**"回正时老是低头"的真因是摄像头装反了，不是程序在控制它低头。**

这也解释了为什么"抖动"看起来像参数问题：没有目标时 `tilt` 恒定不变，
偶尔检测到人（比如手、鼠标）时又跳一下，形成假抖动。
