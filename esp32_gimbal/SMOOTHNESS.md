# 丝滑度改造方案：从 50Hz 到 333Hz

> 2026-11-16 晚。用户的对照实验很有价值：
> **「大疆 Pocket 3 没什么算力，但真的很丝滑」**
> 这个观察点出了本项目"不够跟手"的真正原因。

---

## 一、先说结论：为什么算力低却更丝滑

Pocket 3 的丝滑**不是靠视觉追踪**，而是靠**机械层的高频闭环**。

| 层 | Pocket 3 | 本项目 |
|---|---|---|
| **IMU 姿态内环** | **400~1000 Hz**（陀螺仪 + PID） | ❌ **完全没有** |
| 视觉检测外环 | 30 Hz | 25.6 FPS |
| 电机驱动 | BLDC + FOC 磁场定向 | 有刷舵机，内部闭环 |
| 电机响应延迟 | **18~23 ms** | **230 ms**（实测） |
| 电机角速度 | 300~500 °/s | **46~85 °/s**（实测） |

关键洞察：

```
Pocket 3:   视觉(30Hz) ──→ 目标角度 ──→ [IMU 内环 1000Hz] ──→ BLDC
                                          ↑ 视觉的抖动、延迟、丢帧
                                            全被高频内环吸收掉

本项目:   视觉(25FPS) ──→ 角度指令 ──→ 舵机(PWM 50Hz) ──→ 转
                                          ↑ 每个环节的抖动和延迟
                                            都直接暴露在最终动作上
```

**Pocket 3 的视觉延迟实测 380ms，照样丝滑** —— 因为中间有 IMU 内环兜底。
我们没有内环，所以视觉的每一帧抖动都变成了云台的抖动。

---

## 二、我们能改的：PWM 频率 50Hz → 333Hz

### 现状（`main/gimbal_main.c`）

```c
#define SERVO_FREQ_HZ      50      // PWM 50Hz = 每 20ms 一个脉冲
#define CTRL_PERIOD_MS     20      // 控制循环 20ms
#define SERVO_PERIOD_US    20000
```

**控制粒度 20ms，是 Pocket 3 内环（1ms）的 1/20。**

### 为什么能提到 333Hz

DS3120 规格书明确写着：**控制频率 50–330 Hz**
（[来源](https://smartmodelismo.pt/produto/servo-ds3120-digital-25kg-0-17sec6-8v-dsservo/?add-to-cart=67275)、[来源](https://www.taiwaniot.com.tw/product/%E5%8E%9F%E5%BB%A0dsservo-%E9%81%94%E7%9B%9B-ds3120-mg-%E6%95%B8%E7%A2%BC%E6%95%B8%E5%AD%97%E8%88%B5%E6%A9%9F180%E5%BA%A6-%E9%87%91%E5%B1%AC%E9%BD%92%E8%BC%AA-20kg-%E9%80%81%E9%87%91%E5%B1%AC%E8%88%B5/)）。

我们一直只用了最低档 50Hz。

### 分辨率反而更好（反直觉，但算得清）

```
LEDC 时钟 80MHz，分辨率上限 = log2(80e6 / freq)

  333 Hz: log2(80e6/333) = 17.87 位 → 14 位可用 ✓
          周期 3000us / 16384 级 = 0.183 us/级
          角度分辨率 = 0.183/3000 × 180° = 0.011°/级

   50 Hz: 周期 20000us / 16384 级 = 1.22 us/级
          角度分辨率 = 1.22/20000 × 180° = 0.11°/级
```

**分辨率提升 10 倍**，因为占空比的相对精度变高了。

### 需要同步改的三处

```c
// 1. 频率
#define SERVO_FREQ_HZ      333            // 原来是 50

// 2. 周期（us_to_duty 的换算基础）
#define SERVO_PERIOD_US    3003           // 1000000/333 = 3003（原来是 20000）

// 3. 控制循环（跟随 PWM 周期，避免指令堆积）
#define CTRL_PERIOD_MS     3              // 原来是 20
```

**⚠️ 第 2 项最容易漏**：`us_to_duty()` 用 `SERVO_PERIOD_US` 做分母，
不改的话脉宽会全部算错（1500us 在新周期下变成 50% 占空比 = 指向极限位置，可能撞限位）。

### 风险与验证

| 风险 | 应对 |
|---|---|
| 舵机不支持高频 | DS3120 规格书写 330Hz，333 略超，可退到 250Hz |
| 舵机高频下发热/抖动 | 跑 5 分钟摸温度，观察有否异响 |
| 控制循环太快抢 CPU | 20ms→3ms 后主循环负担增加，但只做几次浮点运算，可忽略 |
| 脉宽算错导致撞限位 | **改完必须先发 `P 0 0` 验证中点，再小步试 ±10°** |

## 三、还不够：真正的"丝滑"需要速度环

即使提到 333Hz，**仍然没有解决根本问题**：

当前控制方式是**位置式**：视觉算出目标角度 → 直接下发角度 → 舵机自己转过去。

舵机内部虽然有自己的位置环，但我们**无法访问它的速度环**，也无法在它转动过程中干预。

Pocket 3 的做法是：给 BLDC 一个**目标角速度**，由 FOC 驱动，随时可以加速/减速/反向。

### 可行的折中：轨迹插值

既然只能给位置，那就**把一帧的角度变化拆成多个小步，在 3ms 的控制循环里逐步下发**：

```c
// 视觉每 40ms 给一个新目标（25FPS）
// 但控制循环每 3ms 跑一次，中间插值 13 次
static float g_target_pan = 0, g_target_tilt = 0;   // 视觉给的目标
static float g_pan = 0, g_tilt = 0;                 // 当前输出

void update_interp(uint32_t dt_ms) {
    // 每 3ms 走完剩余距离的 1/4（指数逼近，比线性更平滑）
    const float k = 0.25f;
    g_pan  += (g_target_pan  - g_pan)  * k;
    g_tilt += (g_target_tilt - g_tilt) * k;
    apply_servos();
}
```

现有的 `S` 命令（缓动）就是这个机制的雏形，但它是**全局固定时长**（`g_slew_ms`），不是按帧自适应。

**改进方向**：让缓动时长 = 视觉帧间隔（40ms），这样舵机在两个视觉帧之间平滑过渡，
而不是"收到新角度 → 猛地跳过去 → 等下一帧"。

这个已经在固件里了（`S <ms>` 命令 + `update_slew`），**只需要上位机在启动时发一次 `S 40`**。

## 四、物理上限：必须承认做不到的部分

| 指标 | Pocket 3 | DS3120 | 差距 |
|---|---|---|---|
| 电机类型 | BLDC + FOC | 有刷直流 | 本质差异 |
| 响应延迟 | 18~23 ms | 230 ms | **10×** |
| 角速度 | 300~500 °/s | 46~85 °/s | **6×** |
| 角速度控制 | ✅ 可给速度指令 | ❌ 只能给位置 | 无法弥补 |
| IMU 反馈 | ✅ 1000Hz | ❌ 无 | 无法弥补 |

**有刷舵机 + 无 IMU 的组合，做不到 Pocket 3 那种"手到眼到"的手感。**

能改善的是：
1. ✅ 控制粒度 20ms → 3ms（PWM 提速）
2. ✅ 帧间插值（`S 40` 缓动）
3. ✅ 变步长消除死区振荡
4. ✅ 消除视觉抖动（裁切框也参与反馈 + EMA 平滑）

**不能改善的**：舵机本身的 230ms 惯性。

如果真需要 Pocket 3 级别的手感，硬件必须换：**BLDC 云台（如 SimpleBGC/BaseCam）或带 IMU 的三轴无刷稳定器**。
那是一个完全不同的成本量级（¥1000+ vs ¥30）。

## 五、实施顺序

按性价比排序：

| 优先级 | 改动 | 预期收益 | 成本 |
|---|---|---|---|
| **P0** | 修 `invert_tilt` + 变步长 | 消除振荡（已实测的 bug） | 改 C++ 重编译 |
| **P1** | 上位机发 `S 40`（帧间插值） | 动作变平滑，无跳变 | **改一行，零风险** |
| **P2** | PWM 333Hz + 控制循环 3ms | 响应粒度提升 6.7× | 改固件重烧 |
| P3 | 换 BLDC 云台 | 达到 Pocket 3 水平 | ¥1000+ 硬件 |

**P1 是最容易见效的**：现在云台收到新角度就硬切过去，如果改成 40ms 缓动，
在 25FPS 下正好是一帧的时间，舵机会在"这一帧到下一帧"之间平滑移动，
而不是"跳一下、停 40ms、再跳一下"。
